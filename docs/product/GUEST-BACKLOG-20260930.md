# VERTEX VISION — гостевой продуктовый backlog

Дата: 30.09.2026. Статус: гипотезы для проверки, не выпущенные функции.
Аудитория: гости и туристы из Узбекистана и других стран; индивидуальные поездки, пары, семьи и группы.

## Ограничения

VISION — платформа, Views — первый активный модуль. Остальные 18 направлений остаются Coming Soon; этот документ не активирует их. JARVIS остаётся отдельным проектом. Существующие календарь, бронирования, консьерж, задачи, такси и конструктор поездки не считаются новыми идеями. Предложения ниже — новые пользовательские возможности поверх этой основы.

Ранжирование качественное: предполагаемый охват, тяжесть проблемы, влияние на доверие/бронирование и возможность Views отвечать за результат. Аналитика воронки, разбор обращений и интервью для данного ранжирования не предоставлены. Цифры прироста выручки/конверсии не прогнозируются. Преимущество перед альтернативами — проверяемая гипотеза, а не доказанное превосходство над всеми конкурентами.

## Границы обещаний

- G01: не обещать бесплатное переселение или денежную гарантию без утверждённой политики и резерва ресурсов.
- G02: валюта отображения отделена от валюты фактического списания; неизвестные банковские комиссии явно не определены. Успех платежа/возврата только по проверенному результату провайдера. Первым этапом может быть прозрачный расчёт без приёма платежей.
- G03: не кешировать публично коды дверей/документы; доступ выдаётся по политике конкретной брони и отзывается после неё. Истёкшие офлайн-данные помечаются; закрытие доступа учитывает ограничения работы без связи.
- G04: срок показывается только после согласования с исполнителем; аварийная помощь отделена от обычной сервисной заявки. Не обещать круглосуточное исполнение без команды.
- G05: первые проверенные интерфейсы — RU, UZ, EN; другие языки подключаются с оценкой качества. Не определять язык по гражданству без выбора пользователя. Перевод не заключает договор и не подтверждает изменение брони.
- G06: пожелания задаёт пользователь. Не выводить здоровье, религию и другие чувствительные признаки из поведения. Измерение Wi-Fi — датированный результат, не постоянная гарантия скорости.
- G07: отсутствие свободного окна означает отказ или альтернативу, не фиктивное подтверждение.
- G08: в Views MVP достаточно заявленного гостем ETA и работы менеджера. Реальные рейсы/поезда/перевозчики — после договоров и интеграций; изменения цены/брони только с подтверждением гостя. Модули Coming Soon не активируются ради прототипа.
- G09: не собирать паспортные данные без утверждённой необходимости, защиты, регионов хранения и retention. Не выдавать собственный экран за официальный документ; открытый API E-mehmon не подтверждён этим исследованием. Обязательные процедуры не откладываются из-за низкого места удобной фичи в рейтинге.
- G10: отзыв приглашения, срок действия, проверка личности при доступе к чувствительным данным; не передавать паспорт и платёжные данные всей группе.

## Проверка приоритетов

Предлагается сначала разобрать фактические обращения Views и провести интервью с местными и международными гостями, включая семьи. После обязательного технического RC проверить G01/G03/G04 и прозрачный расчёт G02 на ограниченном пилоте. Пилот 30–50 проживаний пригоден для проверки сценариев и сбоев, но не доказывает статистически значимый рост конверсии.

Главная продуктовая метрика: доля завершённых проживаний без критической нерешённой проблемы. Дополнительно — воронка подтверждения, время заселения, обращений на проживание, время решения, повторные жалобы, отмены и фактическая стоимость обслуживания. Не оптимизировать скорость закрытия задач ценой фиктивного решения проблемы гостя.
