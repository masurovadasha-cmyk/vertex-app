# Vertex 1.11-demo / quality1

## Scope
This is an incremental repair of the existing Vertex application, not a replacement or a production launch. JARVIS is not part of this application. Changes preserve the confirmed catalog and all 16 existing photos. No additional external listings, photos, prices, credentials or customer data are included.

## Responsibilities
- `rental-domain.js`: pure validation, calendar-date arithmetic, operational metrics and immutable snapshots. No browser, network or persistence dependencies.
- `rentals.js`: rental use cases and the existing local-storage adapter. This module owns bookings, listings, favorites, date blocks and discussions. It backs up corrupt raw data before the next write; an unsuccessful backup/write refuses the change.
- `host-console.js`: host presentation and navigation. Reads immutable rental snapshots and invokes rental use cases. It has no independent booking ledger, hard-coded earnings, fake guests, copied calendar or independent message thread.
- `host-console-more.js`: secondary views and explicit links to available modules. Confirmed catalog editing and photo uploads are marked unavailable; local demo listings have an actual editor.
- `group.js`: failed task/package writes restore the last committed in-memory state. Calendar arithmetic uses the shared date rules, not comparisons between UTC dates and local-midnight timestamps.
- `concierge-server/atomic-store.mjs`: single-process serialized transactions. Readers receive copies of committed state; concurrent mutations serialize; failed writes do not poison the queue. Temporary-file writes use exclusive creation and atomic rename. This server is not wired into the public static app.

## Compatibility
Legacy local rental/CRM records without a currency retain USD semantics. Unknown prices remain unknown. Different currencies are reported separately, never silently converted or summed. Invalid persisted records cannot be inserted as unescaped HTML numeric fields. Read-only catalog data cannot be shadowed by a duplicate local listing ID.

The Android web assets are generated by `scripts/sync-android.cjs`. Native install messaging and disabled service-worker registration are preserved. No newly signed APK is claimed by this patch.

## Verification
- Existing five unit suites plus 35 new rental-domain tests.
- Six server tests, including isolation, live delivery, revocation, concurrency and failed-write recovery.
- `scripts/browser-quality.py`: 52 assertions in Chromium with real DOM interaction and an explicit in-memory storage double. Four viewport widths, cross-time-zone dates, corrupted data, failed saves, calendar month/property selection, editing, search, safe discussion text and modal styling.
- Browser images use reduced-motion preference to capture settled UI, not intermediate animation frames.
- `scripts/check-release.cjs`: JS/CSS parsing and local resource validation for web and Android.
- Cloudflare dry-run validates packaging; it is NOT a deployment.

## Remaining production work
The public app is a local demo. Authentication/authorization, database tenancy, OTA availability, payments, payouts, cross-device delivery and actual operator messaging are not connected. Local demo role-switching is not a security boundary. The standalone concierge server still requires deployment, backups, TLS, operational monitoring, load testing and a deployment-specific security review. A complete absence of defects is not asserted.

## Reproduction
`npm install`, `npm test`, `npm run sync:android`, `npm run check:deploy`.
For DOM checks: Python 3, `playwright==1.57.0`, `beautifulsoup4==4.14.3`, a Chromium installation, then `python scripts/browser-quality.py`.
The current source still includes legacy global UI modules. Incremental migration should use the same domain/application/presentation separation rather than adding more parallel data stores.
