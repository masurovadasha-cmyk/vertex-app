# Vertex: MVP сервиса аренды жилья

## Цель и формат

Демонстрация основных сценариев сервиса наподобие Airbnb под брендом Vertex. Это собственный прототип, без копирования бренда или обещания полной функциональности Airbnb. Результат — веб-интерфейс и устанавливаемый Android APK.

Текущий MVP работает с локальными данными одного устройства. Чат, звонки, объявления, отзывы и бронирования демонстрационные. Деньги не списываются, реальные объекты не бронируются. Карта OpenStreetMap требует интернета.

## Роли

- Гость: найти жильё, сохранить избранное, посмотреть условия, отправить запрос на бронирование, отменить запрос.
- Хозяин: добавить объявление, увидеть заявки, подтвердить или отклонить заявку.
- Менеджер: вести клиентов в CRM, показывать переписку и звонки.

Переключение ролей в демо свободное. Это не авторизация и не разграничение доступа.

## Функциональность версии

| Раздел | Сценарий | Критерий готовности |
|---|---|---|
| Каталог | Направление, даты, гости, максимальная цена, тип жилья, Wi-Fi, сортировка | Показываются подходящие объявления, есть пустое состояние |
| Объявление | Фото направления, описание, вместимость, удобства, хозяин, демо-отзывы | Информация открывается из карточки; указано, что объект условный |
| Избранное | Добавить и убрать жильё | Выбор сохраняется после перезапуска |
| Стоимость | Ночи × цена + уборка + сервисный сбор | Полная разбивка видна до отправки запроса |
| Бронирование | Имя гостя, даты, число гостей, подтверждение условий | Создаётся локальный запрос с уникальным номером, без оплаты |
| Доступность | Проверка дат, вместимости и пересечений | Нельзя отправить два активных запроса на один объект с пересекающимися датами на этом устройстве |
| Поездки | Список заявок и их статусы; отмена | Отмена требует отдельного подтверждения и освобождает даты |
| Кабинет хозяина | Новое объявление; список заявок | Объявление появляется в каталоге, заявка подтверждается или отклоняется |
| Календарь хозяина | Месяцы, выбор объекта, свободные и занятые ночи, блокировка диапазона | Закрытые даты исключаются из поиска и бронирования; открыть даты можно без удаления заявок |
| CRM | Карточки клиентов, поиск, статусы, бюджет, заметки | Локальное сохранение; новый запрос бронирования создаёт карточку клиента |
| Чат | Переписка с тестовым клиентом | Исходящее сообщение и явно обозначенный демо-ответ сохраняются |
| Звонки | Экран разговора, таймер, завершение, история | Явно показано отсутствие передачи звука; телефонный набор доступен только по указанному номеру |
| Карты | Выбор достопримечательности, масштабирование, внешний маршрут | Интерактивная карта Стамбула и объяснение необходимости интернета |

## Правила демонстрационного бронирования

1. Выезд позже заезда; заезд не в прошлом; максимум 365 ночей.
2. Гостей не больше вместимости объекта.
3. Уборка — $25; сервисный сбор — 10% от стоимости ночей, округлённый до целого доллара. Это условные тарифы Vertex для демонстрации, не тарифы Airbnb.
4. Статусы: «Запрос отправлен» → «Подтверждено» / «Отклонено»; гость может отменить активную заявку.
5. Активные заявки резервируют даты только в локальной демонстрации. Это не проверка реальной доступности.
6. Повторная отправка пересекающегося запроса блокируется. Отменённые и отклонённые заявки сохраняются в истории.

## Данные

- Объявление: id, название, город, цена за ночь, вместимость, тип, Wi-Fi, описание, хозяин, иллюстрация.
- Заявка: id, снимок объявления и цены, имя гостя, заезд, выезд, гости, сумма, статус, дата создания.
- Избранное: список id объявлений.
- Клиент CRM: имя, город, телефон по желанию, сумма сделки, статус, заметки, переписка, история звонков.

Избранное, объявления, заявки и CRM хранятся в localStorage. Удаление приложения или очистка его данных удаляет их. Синхронизации между телефонами нет.

## Вне демонстрационного MVP

Реальная регистрация и роли, серверная база, платежи и возвраты, проверка личности, договоры, налоги, настоящая переписка и VoIP, push-уведомления, загрузка фотографий, мировая карта объектов, синхронизация календарей iCal, цены по отдельным дням, модерация и реальные отзывы.

Для рабочего сервиса следующий этап: API и база данных, авторизация, транзакционная проверка доступности, интеграция платежей, серверный чат, хранение фотографий и мониторинг. Нельзя принимать реальные бронирования на основе этого локального прототипа.

## Сценарий показа

1. Найти жильё в Стамбуле на будущие даты для двух гостей.
2. Сохранить объект в избранное и открыть подробности.
3. Проверить расчёт и отправить демо-запрос.
4. Открыть «Мои поездки», затем «Хозяин» и подтвердить заявку.
5. Убедиться, что статус обновился, а пересекающиеся даты заняты.
6. Открыть созданного клиента в CRM, отправить тестовое сообщение и показать демо-звонок.
7. Открыть карту, затем добавить собственное демонстрационное объявление.
8. Перезапустить приложение и проверить сохранение данных.
