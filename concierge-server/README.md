# Vertex Concierge — серверный модуль, не опубликован

Это отдельный прототип реального мессенджера. В отличие от локального демо в APK, сообщения передаются между браузером гостя и кабинетом оператора через сервер и SSE. Интерфейс по-русски. Автоматических ответов от вымышленного оператора нет.

## Реализовано в исходниках

- Кабинет оператора с паролем из окружения.
- Подтверждение готовности апартаментов, данные гостя и срок действия доступа.
- Персональное приглашение с криптографически случайным токеном; на сервере хранится его хеш.
- Автоматическое приветствие и памятка: адрес, этаж, квартира, дверь, Wi-Fi, мини-чип, правила, телефоны.
- Сессии HttpOnly / SameSite, Secure при HTTPS; проверка Origin, ограничение попыток входа.
- Переписка с серверным сохранением и доставкой событий открытым клиентам.
- Отзыв приглашения и доступа к данным.
- WebRTC-сигнализация, входящий/исходящий аудиозвонок и завершение. Для звонков требуется TURN-конфигурация и разрешение микрофона.

## Запуск локально

Node.js 22+. Скопируйте `.env.example` в `.env`, задайте уникальный `OPERATOR_PASSWORD` от 16 символов. Не отправляйте пароль в чат и не коммитьте `.env`.

```powershell
node --env-file=.env server.mjs
```

Откройте `http://127.0.0.1:8787`, войдите оператором, создайте проживание с ТЕСТОВЫМИ данными. Ссылку гостя откройте в другом браузерном профиле. В одном профиле cookie сессии переключается между ролями.

Приветствие появляется в кабинете гостя автоматически после входа. Доставка самой ссылки по SMS/почте/мессенджеру ещё не подключена; оператор передаёт её вручную. При закрытом браузере push-вызовы и push-сообщения не работают.

## Обязательно до размещения реальных данных

1. Определить VPS или Node-хостинг; текущий сервер нельзя напрямую запустить как Cloudflare Worker.
2. Настроить домен/HTTPS и reverse proxy, `PUBLIC_ORIGIN`, длительные SSE-соединения без буферизации.
3. Настроить TURN, проверить звонок между разными мобильными сетями. В текущем прототипе используются серверные TURN-учётные данные; до публичного запуска нужны краткосрочные credentials и ограничения использования.
4. Заменить общий пароль оператора индивидуальными учётными записями, MFA, ролями и журналом доступа.
5. Перенести `.data/state.json` в защищённую базу; добавить шифрование секретов, резервные копии, сроки хранения и аудит. Сейчас файл содержит данные заселения в открытом виде и должен оставаться только в закрытом тестовом окружении.
6. Проверить доступ до заезда и после выезда, политику выдачи кодов, смену кодов после выселения, антиспам и нагрузку.
7. Подключить серверные бронирования: локальные заявки APK пока не отправляются на этот сервер.
8. Подключить APK к согласованному HTTPS-адресу, сделать безопасную обработку микрофона/звонков и push при необходимости.
9. Обеспечить график операторов 24/7. Наличие интернет-соединения не гарантирует круглосуточный ответ.

## Ограничения

Один общий операторский доступ в этой версии. При нескольких активных операторах нет диспетчеризации звонков. Сессии сбрасываются при перезапуске сервера. WebRTC-сигнализация подготовлена, но настоящий голосовой разговор пока не проверен. Не объявлять сервис работающим круглосуточно до развёртывания, проверки и подключения дежурных.

Реальные коды двери и Wi-Fi из примера пользователя не включены в код, APK, документы или тестовые данные.
